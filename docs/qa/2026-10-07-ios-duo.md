## 本地真实 HTTP 闭环

后端的 `MobileTransferLoopbackIntegrationTest` 使用真实 Spring HTTP、控制器、服务、H2、磁盘 blob 与 `MobileRelayClientService`。账户及文件都在测试中创建；外部计费、嵌入模型、撤销列表等外部依赖替换为测试对象，关闭定时任务，持久目录全部隔离。

Java 先执行目录推送、LIST、报价、PULL、桌面 multipart 回传、content、ACK。断言读取内容不提前删 blob；重复 UUID 不重复扣费；ACK 后中转清理而源文件字节不变；跨项目 file ID 被拒绝并退款。文件包含 65,539 字节，覆盖流式客户端的块边界。

随后通过仅本地临时 fixture 接入实际 Swift `ProjectFilesService`：projects → LIST → quote → 明确确认 → PULL → content → ACK → 预览复用 → 关闭删除。Swift 核验整个文件 SHA-256 与测试源一致，Java 额外确认这次仅产生一个 PULL／一次模拟扣费，状态 DELIVERED、blob 已删、桌面原件保留。这个哈希来自测试已知源；生产 API 没有内容哈希，不能据此声称生产客户端验证了来源真实性。

复现时，先用 JDK 21 跑后端测试，并设置 `-Dawd.loopback.fixture=/tmp/awd-duo-loopback-fixture.json`。测试将以 0600 权限写入随机回环 URL 和测试会话，仅等待八分钟；不要打印或提交该文件。iOS `build-for-testing` 后，在生成的 xctestrun 的 WorkdeckTests.EnvironmentVariables 设置 `AWD_LOOPBACK_FIXTURE` 为此路径，只运行 `ProjectFilesLoopbackTests`。成功后 `.done` 触发 Java 的最终断言及 fixture 清理。未提供 fixture 时该专项测试明确跳过；常规 99 项运行用 `-skip-testing:WorkdeckTests/ProjectFilesLoopbackTests`，专项另跑，不能混称跳过即通过。

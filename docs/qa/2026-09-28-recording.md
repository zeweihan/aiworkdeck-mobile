# 2026-09-28 录音与资料库核验

关联：dev-board #978 / #979 / #980 / #981。修复版本：iOS 1.2.1。

## 问题与修复

- iOS 只靠中断通知判断状态，回前台不核对录音机；所有中断被误称为通话。现在用实际录音状态和音频时长对齐 App / Live Activity，回前台尝试恢复，并保留停止入口。
- 相机释放麦克风原来只投递异步任务，激活录音会话可能抢在它前面。现在等待相机串行队列完成释放，并在录音期间阻止相机重新启动及自动改写音频会话。
- 旧停止路径依赖 delegate，再经页面回调保存；源文件在确认保存前即删除。现在 stop 关闭文件后由服务自行保存，开录即保存项目/位置/时刻快照。可用草稿在启动/回前台恢复，同一 ID 幂等；保存失败不删原件。损坏且无法解码的文件仍保留，不能保证修复已损坏音频。
- 主按钮按真实录音状态优先停止，并有完整 76pt 点击区域。UI 测试曾返回 hit point (-1,-1)，明确触摸区域后后台返回与停止链路通过。
- iOS 回放显式切换为 playback 音频会话，录音提供播放/暂停按钮；正在录音时不允许播放其他媒体抢麦克风。
- 四端资料库均有“全部 / 录音”筛选。安卓/鸿蒙/小程序在页面重建时恢复录音模式和停止控件；小程序计时扣除中断时间、权限请求单飞，保留平台后台录音限制提示。
- 安卓/鸿蒙保存音频时，manifest 成功前保留源文件；阻止保存期间重复停止/开始；保存结果可见。其异常源文件尚不具备 iOS 同等的跨进程草稿恢复机制。

## 实测与证据边界

- iOS 26.5 模拟器：65 项 XCTest 通过，包含真实 AAC 录制、注入音频中断、通过 StopRecordingIntent 停止、播放解码及重复停止幂等；草稿保留/幂等入库与时钟恢复测试。
- XCUITest：实际点击录音、返回主屏、回 App、停止、保存提示、资料库筛选、播放与暂停通过。没有假录音截图参与该验收，测试账号/项目仅 Debug 注入，不上传。
- Node：136 项通过；TypeScript、共享契约、配色检查通过。
- 安卓：JVM 单测与 intlDebug / cnDebug 编译通过，包括 manifest 写入失败仍保留录音源文件的回归。
- 鸿蒙：DevEco ArkTS 检查、未签名 debug HAP 构建通过。
- 桌面/云中转：47 项定向测试通过（25 个 HTTP 编排、2 个命名/日期、20 个中转存储）。音频被接受为 audio，桌面取件归档至“现场录音/日期”，fileType=m4a，写入后 ACK。后端原目录全量测试编译存在与本任务无关的重复类，因此用临时测试目录编译这三个原测试类，复用当前主代码编译产物；未修改后端源码。
- 未验证：实体 iPhone 来电/Siri/锁屏与灵动岛按钮交互、安卓/鸿蒙真机中断、小程序真实微信后台行为、用户账号和用户桌面实际接收。模拟器成功不等于以上真机路径已复现通过。

## 复测

在 iPhone 选择项目 → 录音 15 秒 → 锁屏 30 秒 → 返回并停止；资料库切“录音”，播放验证前后台两段都有声音。另从锁屏停止一次、来电中断后停止一次。桌面同账号在线时，在项目“现场录音/日期”找到 m4a；手机队列应从“已暂存”变成“已落盘”。

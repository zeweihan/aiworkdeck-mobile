## 1. 建议与范围

把 iOS 升级成“项目工作区 + 现场采集”。展开后左侧项目、右侧项目资料；收起后保持同一项目、文件与浏览位置，转成逐级导航。现场采集独立打开，继续提供原来的照片、录像、录音；新增显式的“本人同框”照片模式。

“项目资料”的范围需先确定：现有手机图集只有手机采集的照片、录像与录音，桌面项目里的 Word、PDF 等尚未接入。建议工作区分别提供“项目文件”和“现场记录”，前者接桌面文件列表，后者复用本地图集。这项范围问题已向用户提出；未答复前不把本地图集当成全部项目文件，也不擅自扩展成手机文档编辑器。

本次以双摄照片／同步帧同框记录为目标，连续双摄录像不作为首版必做；保留已有单摄录像。两路拍摄的具体输出方式由硬件原型验证决定，不能先承诺全分辨率、同一曝光时刻或无缝切镜。

本次不发版、部署、上传 TestFlight 或改 App Store 素材。代码通过审阅及约定测试后主动合并；未通过的专项验收不能用模拟素材替代。

## 3. 现有代码审计

以下是源码观察，不是运行验证：

- `ios/project.yml`：仅 iPhone、仅竖屏；最低 iOS 17。不能只解除竖屏限制，还须同步处理预览和输出方向。
- `ios/Sources/App/WorkdeckApp.swift`：选项目后进入相机；图集、队列、设置为全屏覆盖页。
- `ios/Sources/Features/Library/LibraryView.swift`：本地影像按项目筛选，浏览项目与拍摄目标不同；此区别不能在双栏改造中丢失。
- `ios/Sources/Services/CameraService.swift`：普通 AVCaptureSession + 单后摄；没有双摄管线。预览随 view bounds 变化，但没有完整的旋转协调机制。
- `ios/Sources/Features/Home/HomeView.swift` 与 `AppModel.store`：当前在采集回调落库时读取选中项目。双栏新增随时切项目后，会产生错归档风险，应在快门时锁定目标，录像／录音期间不改其归属。
- `CaptureManifest` 与 `EvidenceStore`：有原始文件 SHA-256、设备时间、GPS 精度、设备信息；TSA 为 nil。`Backend.upload` 未上传完整 manifest。因此“同框图 + 两路原件 + 关联信息抵达电脑”必须补足传输和桌面落盘，不能只改手机预览。
- 主仓 `MobileTransferController`／`MobileTransferService` 已有 LIST、PULL 等中转接口，手机尚未接入共享 API 契约。LIST 不扣费，但依赖桌面在线；PULL 可能计费。
- `MobileRelayClientService.handleListCommand` 与服务端目前最多返回 2000 个文件，且不返回空目录、没有截断标记。首版需明确列表完整性，不得默认为完整目录镜像。

桌面项目必须使用 `(deviceId, projectKey)` 复合身份，不能把本地 projectKey 直接当云端 projectId。跨项目请求要防止旧响应覆盖新选择。

## 4. 交互设计

### 项目工作区

```text
展开／宽空间
┌─────────────────┬─────────────────────────────────────┐
│ 项目             │ 当前项目                            │
│ 搜索项目         │ 项目文件  |  现场记录                │
│ ▸ 项目甲         │ 搜索／筛选                           │
│   项目乙         │ 文件夹／文件或现场影像               │
│   项目丙         │ 文件名、类型、位置／传输状态          │
│                  │                                     │
└─────────────────┴─────────────────────────────────────┘
系统工具栏：采集、传输队列、设置；由系统安排所在边缘

收起／窄空间：项目 → 项目资料 → 文件预览
```

1. 使用稳定的 `NavigationSplitView`，不按设备名手写两套页面。展开时露出项目栏；收起保留当前内容层级，返回才能回到项目列表。
2. 打开文件时以右侧详情／系统预览为主，可全屏阅读。不强行挤成项目、文件、预览三栏；返回恢复筛选和滚动位置。
3. 当前浏览项目与采集归档目标明确区分；从项目发起采集时显式带入目标。开始拍摄后冻结本次目标；折叠、旋转、返回前台均不得改归属。
4. 资料列表显示加载、空项目、桌面离线、请求超时、重试及本地可用状态。离线仍能打开本地记录。若缓存远端清单，明确最近更新时间，缓存按账号、区域、设备和项目隔离。
5. 文档下载在用户点击后进行，先展示已有计费规则与报价，再确认传输；滑过列表和打开项目不自动发起收费下载。首版不新增 Word 编辑、协作或同步冲突处理。
6. 从路径呈现文件夹时只作为浏览结构，不把展示路径当可信本地存储路径；远端返回的文件名不能越界写入缓存。

### 折叠屏采用的模式

- **列表与详情并排**：利用新增空间呈现信息层级，不只是放大原来的手机画面。
- **状态连续**：保持项目、选中文件、页内位置、筛选、下载和采集任务，不在展开时重置首页。
- **适应应用窗口**：Duo 同时打开两个 App、键盘、系统画中画都会缩小可用空间；不能仅测试展开全屏。
- **半折避让**：书本姿态避免按钮和重要图像跨折痕；桌面姿态上方预览、下方快门和模式。功能在所有姿态保持可达。
- **系统栏优先**：采用原生导航／工具栏适应左右边缘迁移；自定义采集控件遵守 safe area 和 reserved regions。
- **辅助功能**：动态字体、VoiceOver、减少动态效果、深浅主题都纳入验收，触控目标不因双栏变小。

这些模式依据苹果设计与布局讲解，以上映射到项目界面的选择是本方案的设计判断。

### 本人同框拍摄

相机提供明确的“本人同框”开关。默认仍是普通采集；设备不支持、资源不足或摄像头被占用时说明原因。不得静默退成单摄并继续标为同框。

预览以现场为主，拍摄者置于次要窗口；展开时可以并排，半折时预览和操作分区。展示与导出可采用不同布局：归档用同框图将两幅完整画面放在独立区域，避免人物小窗遮住文件内容；附项目、设备记录时间和组号。合成图标明是合成记录，两路原件独立保留。

按下一次快门只提交一组。两路均有效、属于同一次采集、在实测确定的同步容差内，才能提示成功。失败、超时、切镜间隙或任一路缺失时提示未完成，不能拿旧人像帧补齐；已取得的原始素材保留为明确的未完成草稿，支持重试和清理。

## 5. 双摄采集与归档方案

先做硬件原型，验证 `AVCaptureMultiCamSession`、可用镜头组合、格式及资源成本。明确两种输出的区别：

- **双路照片**：可得到照片输出，但对两次调用不能宣称硬件同一曝光；必须核验拍摄时间与输出能力。
- **同步视频帧快照**：更适合“同一时刻的双视角”，但分辨率与处理方式不同，应标明是同步帧记录，不能叫无处理相机 JPEG 原图。

原型报告后选择一种首版路径。不能把 UI 截屏当作采集原件，不能用后摄照片加任意历史自拍构造记录。

每组数据的最小结构：组 UUID、拍摄时锁定的项目、两路独立素材及哈希、镜头／方向、共同时间基准下的采集时间及差值、设备时间、位置与精度（含定位样本时间）、合成图及哈希、构图版本、缺失／中断状态。设备时间与服务端接收时间分别记录；离线不声称已获得可信时间。

落盘流程：先保存两路素材及其哈希，再保存派生图，最后原子提交组清单。中途退出或存储不足不能出现“完整组”假状态。照片回调必须保留快门时的项目快照，不在回调时重新读取当前浏览项目。

传输流程需要端到端契约：两路原件、派生图和组清单共同归档；所有成员落盘并验哈希后才显示该组已抵达。失败重传幂等，部分成功不得删除本地剩余原件。移动端、云中转与桌面接收端分别加兼容测试，旧单摄记录无需迁移成新结构。

生命周期按组处理：图集提供组级删除确认；若单个成员缺失，整组显示不完整。更新 `EvidenceStore.sweepOrphans` 的引用识别，避免启动时误删配对原件或合成图。遵守现有“同时存入系统相册”开关；原件与合成图的导出范围明确展示，不重复写入。补组删除、缺失成员、启动清理与相册导出测试。

这套设计增加的是可复核的现场记录材料。人像可见、账号登录、哈希匹配各自证明的范围不同，不能直接显示“律师身份认证成功”“本人核查认证通过”或“可信时间已认证”。本次不新增人脸库、身份核验服务、TSA 或法律效力承诺。

## 7. 测试矩阵

**自动化基础检查**：契约生成一致性、`node contract/tools/check.mjs`、`npm run typecheck`、`npm test`、iOS WorkdeckTests；涉及后端时加 API 契约与中转集成测试。双摄组补失败回滚、断点恢复、哈希、旧数据解码、幂等和错项目回调测试。

**UI E2E**：普通 iPhone；Duo 外屏、内屏横／竖、书本半折、桌面半折、双 App 分屏。执行项目→文件→预览→折叠→展开→返回；检查项目、文件、筛选与位置未丢。覆盖请求乱序、离线、空列表、长名称、2000 项边界、删除确认、权限拒绝、大字体与中英文。

**既有回归**：保留录音后台→返回→停止→图集→播放的 XCUITest；补录音中折叠切换、录像停止与归档、普通照片相册开关、上传失败重试。自动化测试使用隔离目录和合成数据，不修改用户真实项目或已有手机记录。

**真实双摄 E2E**：两路可辨识的动态计时／事件目标，核验样本时间基准和配对；横竖方向、镜像、折叠切镜、权限关闭、来电／相机占用、前后台、系统压力、存储不足、连续采集。检查两路原件、同框图、关联清单经重启及上传后仍一致；双路不同步或缺帧时必须拒绝成功。

普通双摄 iPhone 真机可验证通用采集；Duo 特有的内外摄切换需 Duo 实机或 Apple 提供的相应硬件验证条件。Duo 模拟器能验证布局，不能代替真实多摄采集。测试替身只验证应用逻辑，在报告中独立标识，不能计作硬件通过。

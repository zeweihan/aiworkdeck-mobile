## B. Paid Applications Agreement + 银行与税务（iOS 内购的硬前提）

没有这份协议，内购商品**在沙盒里都拉不出来**，我这边连联调都做不了。两个主体各做一次。

1. App Store Connect →「业务」→「协议」→ 找到 **Paid Applications**（付费应用）→ 点「接受」。
2. 接受后会出现三块待办，**缺一不可**，缺任何一块协议状态都停在「处理中」：
   - **联系人信息**：至少要填财务联系人、技术联系人、法务联系人（可以是同一个人）。
   - **银行账户**：
     - 香港主体 → 香港银行账户（要 SWIFT/BIC、账号、开户名必须与 Apple 开发者账号主体名称一致）
     - 京微资易 → 大陆对公账户
     *开户名与主体名不一致是最常见的打回原因。*
   - **税务表单**：
     - 香港主体 → 美国税表填 **W-8BEN-E**（非美国实体），另需填香港税务信息
     - 京微资易 → 中国税务信息 + W-8BEN-E
3. 三块都提交后，协议状态变为「有效」。资料齐全的话通常几天内完成。

**回款周期**：按自然月结算，约月结后 45 天到账。

**做完把什么给我**：两个主体的协议状态（有效 / 处理中 / 缺哪块）。不涉及密钥。

## C. 微信小程序虚拟支付（你专门问的这一项，写细一点）

### 先理解它是什么

微信不允许小程序里卖虚拟商品时用普通微信支付。它单独做了一套叫「虚拟支付」的通道：
- 你要在小程序后台**另外开一个二级商户号**（不能复用官网现在用的那个商户号）；
- 客户端调 `wx.requestVirtualPayment`，微信**按设备类型自动路由**：
  安卓/鸿蒙/Windows 走微信支付，**iOS 走 Apple 支付**（苹果的 12% 佣金已包含在费率里）；
- 商品要在后台配成「道具」或「代币」。**我们选道具**——代币的兑换比例一旦发布不可修改，
  而我们的 Credits 是「1 元 = 100 分」的面值模型，用固定档位的道具更稳。
- 费率（工具类）：安卓/鸿蒙/Windows **当前 1%**（标准 10%，现在是优惠期）；**iOS 12%**。

### 开通前先确认三个条件

- 小程序主体已认证 ✅（我们是企业认证，appid `wx67b9a7d0449be0b4`）
- 小程序类型为企业/事业单位/个体工商户 ✅
- 主体信息完备（缺就按后台给的修改链接补）

### 六步开通（全程约 2–9 个工作日，两段审核是串行的）

1. 登录 https://mp.weixin.qq.com → 左侧栏找到 **【虚拟支付】** → 点「开通」。
   *如果左侧栏没有这一项，说明资质条件没满足，先看上面三个条件。*
2. **阅读协议**，勾选「我已阅读并同意上述条款」，下一步。
3. **提交商户资料**，开通新的二级商户号。要准备：
   - 企业营业执照
   - **提现账户**：官方页面只写「提现账户」，但社区反馈目前个体户只支持**对公账户**，
     企业主体请直接准备对公账户，以后台实际表单为准。
   - **支付管理员信息**：**建议直接填公司法人**——这样可以跳过第 5 步之前的「账户验证」环节，
     省一轮等待。
4. **等审核，1–7 个工作日**。审核状态不会推送，下次进入页面时才能看到。
5. **账户验证 + 扫码签约**。（支付管理员配置为法人则跳过账户验证，直接扫码签约。）
   签约完成后资料会**再提交一次审核，约 1–2 个工作日**。
   *这两步不一定即时完成，可以退出页面，之后再进来接着走。*
6. 状态变成「已签约」后，【虚拟支付】栏目会变成完整的**商户管理后台**，里面有：
   - **基础配置**：`appid` / `offerid` / **AppKey（现网 + 沙箱两把）** / 发货订阅设置
   - **道具管理**：上传道具到开发版、发布到现网
   - **资金管理**：余额查询、提现、日账单
   - **交易订单**：查单、退款

### 开通后还要做两件事

- **配「小程序简称」**（【虚拟支付 → 基础配置】里）。
  这是 **iOS 端 Apple 支付的硬前提**——Apple 要展示 display name，不配的话 iOS 端调不起来。
- **道具先别自己建**。等我把档位定义写好（productId 与金额的对应关系要和 iOS/官网对齐），
  我给你一份表，你照着在「道具管理」里录入并发布到现网。

### 做完把什么给我

- `offerid`、二级商户号（这两个不是密钥，直接告诉我）
- **AppKey 是密钥，不要发给我**。请把两把 AppKey 填到官网服务器的 env 里：
  北京 ECS 官网目录的 `.env.local`，键名用 `WXVP_APP_KEY`（现网）和 `WXVP_APP_KEY_SANDBOX`（沙箱），
  同时加 `WXVP_OFFER_ID`。填完告诉我「已填」即可。

### 两个容易踩的坑

- **iOS 端没有沙箱**，只能用现网真实支付测（最低 1 元）。所以联调顺序是先在安卓上用沙箱跑通，
  再上 iOS 用真钱小额验证。
- iOS 端的钱由**苹果结算给腾讯**（自然月结束后 45–60 天），腾讯再转到你的虚拟支付账户。
  安卓端是 T+3。两条线到账速度差很多，对账时别搞混。

## D. 微信开放平台移动应用 + APP 支付（安卓大陆版，可与 C 并行）

1. https://open.weixin.qq.com 注册/登录开发者账号，完成**企业资质认证**（客服页写认证费 300 元/次）。
2. 「管理中心 → 移动应用 → 创建移动应用」，填：
   - 应用名称、简介、图标
   - **Android**：包名 `com.aiworkdeck.mobile.cn`，以及**应用签名（MD5）**
     —— 这个签名我来算给你，等我做安卓端时提供，你先把其他信息填好。
   - **iOS**（可选，同一个移动应用可以同时登记）：Bundle ID `com.aiworkdeck.mobile.cn` + Universal Links

4. 审核通过拿到 **移动应用 AppID** 后，去 https://pay.weixin.qq.com 商户平台
   →「产品中心 → APP 支付 → 申请开通」，提交：移动应用 AppID、应用页面截图、应用商店下载链接。

## E. Google Play Billing（安卓国际版）

你选了走 Google Pay，对应的是 **Google Play Billing**（Play 商店的内购）。

1. **Play Console 开发者账号**：https://play.google.com/console
   用**组织账号**（香港主体，D-U-N-S `77-335-9490`）。组织账号认这个号做身份验证，
   而且能免掉新个人账号「12 名测试者连续 14 天封闭测试」的门槛，可以直接发正式版。
2. **付款资料（Payments profile）**：Play Console →「设置 → 付款设置 → 创建付款资料」。
   要填公司信息、银行账户、税务信息。**没有付款资料就不能创建内购商品。**
3. **内购商品**：等我把档位定好，走 `credits.usd.10 / 20 / 50` 同一套 productId
   （类型选 **一次性商品 / 消耗型**）。这一步如果开了 Play Developer API 我可以用 API 建，
   需要你在 Play Console 里建一个 **服务账号**并授权——到时我给你具体步骤。
4. **分成**：标准是年营收前 100 万美元 **15%**、超出部分 30%。
   注意 2026 年 Google 在推 Expanded Billing Choice 新框架，费率结构在变，
   实际接入前我会再查一次 Play Console 当前页面。

**净收测算**：85% 净收 − 80% 成本 ≈ **每 100 元赚 5 元**，和 iOS 加入小企业计划后差不多，都很薄。

**做完把什么给我**：Play Console 开发者账号状态、付款资料状态。

## F. 支付宝 APP 支付（可选，安卓大陆版第二通道）

比微信宽松，**不要求 App 已在外部应用商店上架**。

1. https://open.alipay.com 用**已完成企业实名认证**的支付宝账号登录。
2. 「移动应用」类目下创建应用，报 Android 包名 + 签名 / iOS Bundle ID（开发期信息即可）。
3. 应用详情页「添加功能」勾选 **APP 支付**（标注「需要签约」）。
4. 用支付宝密钥生成工具生成 RSA 密钥对，上传应用公钥。
5. 提交上线审核（约 1 个工作日）→ 状态变「已上线」→ 再对 APP 支付能力**单独发起签约** →
   签约通过、能力状态变「已生效」才能用于生产。

*注意「已上线」指的是支付宝开放平台内部的审核状态，不是外部应用商店上架。*

## G. 提审前必须实测的两家安卓商店（不是开通，是验证）

这两家我查不到能一锤定音的一手条款，**必须用带充值功能的测试包实际提审验证**，不能凭调研定案：

- **应用宝**：其审核规范里有「应用接入涉及支付功能需接入腾讯支付，若存在第三方支付可能被拒绝」
  的表述，而且**不限定品类**。如果这条真被执行，安卓大陆版在应用宝就只能走腾讯支付。
- **小米**：留有一条较旧的规范「您的应用存在付费项，请联系商务合作」，也不区分游戏与工具类。

华为应用市场相对明确：强制 IAP Kit 只绑定「联运」合作与游戏品类，我们非联运独立发行不受约束。

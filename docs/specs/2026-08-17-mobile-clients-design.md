# AI Workdeck 移动端设计

2026-08-17。两个原生端：iOS（Swift/SwiftUI）与微信小程序（原生 WXML/WXSS/TS）。
核心是尽调现场拍照录像、同步归档到项目目录，加基础文件管理。

## 3. 数据流

```
手机拍摄
  ├─ 原图写入应用沙盒（不进系统相册）
  ├─ 立即算 SHA-256，记录时间 / GPS + 精度 / 设备型号 / 是否强制来自相机
  └─ 生成 manifest（clientMediaId UUID，tsaToken 留空）
        ↓  客户端加密（项目密钥，云端拿不到明文）
  分块上传 → 中转后端（复用 POST /api/files/{id}/upload）
        ↓  中转区只存密文，7 天 TTL
  桌面端上线后拉取 → 解密 → 落到 localRoot 的 现场影像/YYYY-MM-DD/
        ↓  桌面端 ACK 确认落盘
  中转区立即删除 → 手机端标记「已抵达」，提示可清理本地原图
```

四条不变式：

1. **删除由 ACK 触发，不由时间触发。** 7 天 TTL 只是兜底，两个机制不能混。
2. **幂等键是 `clientMediaId`。** 弱网重传、进程被杀重启都不产生重复文件。
3. **项目密钥随配对二维码下发，绝不上行。** 中转区从头到尾看不懂内容。
4. **桌面端离线时手机端必须显示已等待多久。** 桌面端是 Electron，关掉就不轮询；
   这个约束改变不了，就不能藏。

配对：桌面端出二维码 → 手机扫 → 后端签发 `awdt_` 设备令牌（复用
`DeviceTokenService`，与 Office 插件同一套）。

## 4. 一致性口径

两端都原生，一致性不靠共享 UI 代码，靠共享契约：API 形状、状态机、文案词典、
设计令牌。然后**分层**：

- **逐像素一致**：取证拍摄流程（相机、上传队列、归档确认）——肌肉记忆要能通用
- **各自平台化**：导航、设置、文件浏览——iOS 走 HIG，小程序走微信规范

已知能力差，不假装等价：

| | iOS | 小程序 |
|---|---|---|
| 后台上传 | `URLSession` 后台传输 | **不支持**，退出即停 |
| 录像时长 | 无限制 | `chooseMedia` 60 秒（iOS）/ `startRecord` 30 秒 |
| 毛玻璃 | `.ultraThinMaterial` 系统级 | `backdrop-filter`，安卓中低端机降级实色 |
| 设备证明 | App Attest | 无 |

小程序端录像做连续分段，界面明示「本端录像为记录用途，证据用途请用 iOS 端」。

## 5. 视觉

初版被否，原因记录在 `docs/design/variants.html`：浅灰底加白卡片加阴影加三个
彩色大数字并排加蓝色渐变圆角按钮 —— 后台仪表盘与营销落地页的语汇，不是现场
取证器械。且毛玻璃用在纯色背景上等于白做。

重做后各归其位：

- **主界面 = C 仪器极简。** Braun 语汇，210pt 转盘配四刻度与镜头环。现场单手、
  光线差、要快，一个闭着眼睛都能按到的控件胜过任何信息面板。
- **影像浏览 = B 影像优先。** 深色，影像铺满，玻璃条压在影像上 —— 全局唯一
  真正用得上毛玻璃的地方。
- **排版底层 = A。** 字级跨度、发丝线、等宽数字、字距拉开的小标签，三处共用。

令牌单一来源 `miniprogram/styles/tokens.wxss`，iOS 侧 `ios/Sources/Design/Tokens.swift`
逐值对应。底是纯白不是浅灰；分区靠发丝线与留白不靠卡片；层级靠字级跨度不靠颜色；
状态色只做小圆点。

不许写死——国际版与大陆版是同一套 Swift 代码，只换这个值和签名 Team。

尽调影像不经由大陆服务器中转是国际版的合规前提，别为了省事把国际版指回北京。
